2013 – 2015

作る楽しさを、手当たり次第に

最初のころは、とにかく「動くもの」を作ること自体が楽しくて、言語もプラットフォームも選ばずに手を出していました。PHP や Ruby でサンプルを書き、Objective-C と Swift で iOS のアプリを作り、Rails でアプリケーションの組み立て方を学ぶ。「リアルタイムどう書く」のようなお題にも挑戦して、書いたものはとりあえず GitHub に置く、という習慣がこのころにできました。

    2019 – 2020

    Kotlin × AWS で、サービスを丸ごと作る

    サーバーサイドを Kotlin と Spring Boot に据え、インフラまで含めてサービスを一人で丸ごと作り切ることに挑んだ時期です。morning-code という Organization を立ち上げ、API、ブログのサービス、管理画面、DB、Angular のフロントエンドに分けて開発しました。SonarQube による静的解析の環境や、AWS の請求額を通知する仕組みまで、運用を見据えたものも自分で用意しています。

    インフラは AWS CDK でコードとして書くことを徹底しました。Kotlin と TypeScript の両方で CDK を書き、Lambda、ECS / Fargate、AWS Copilot、GitHub Actions によるデプロイの自動化まで、さまざまな構成を試しています。Spring Batch、SQS のコンシューマー、スケジュール実行と、Spring Boot の使い方を一通りサンプルにまとめたのもこのころです。リポジトリの数が最も多いのが 2020 年で、手を動かす量がいちばん多かった時期でもあります。

    2020

    脆弱性を、仕組みで見つける

    サービスを作る側に立ったことで、それをどう守るかにも関心が広がりました。2020 年は、脆弱性の管理をまとめて掘り下げた年です。Vuls を導入し、脆弱性のデータベースである goval-dictionary を AWS 上に CDK で構築し、OVAL の定義と突き合わせるアプリケーションを Spring Boot で書きました。

    コンテナイメージのスキャン（Clair）、依存ライブラリの検査（Snyk）、Go で書いた自作のスキャナーと、守り方を複数の層で比べています。わざと脆弱なライブラリを含めた Docker イメージを用意して、検知の仕組みを確かめることもしました。BCC（eBPF）でのカーネルの観測や、SAML による SSO も、この流れで手を動かしたものです。

    2021 – 2022

    クラウドネイティブを、深く

    インフラの関心が、コンテナを動かすことから、コンテナ群をどう運用するかへと深まった時期です。Kubernetes の上で Spring Boot を動かし、Istio でサービスメッシュを試し、OPA でポリシーを書きました。EKS のクラスターは CDK で組み、試行錯誤のコミットは 60 回に及びます。AWS App Mesh と Cognito を組み合わせた認証つきのマイクロサービス、Terraform Cloud、Windows Server への Elastic Beats の導入と、守備範囲を広げました。

    同時に、「依存関係を新しく保つ」という運用の手間を自動化することにも取り組みました。AWS CDK の新しいリリースを検知し、更新のプルリクエストを自動で作る仕組みを、Python と GitHub Actions で作っています。形態素解析の API や単語ベクトルの可視化など、2017 年に触れた自然言語処理を、使える形の道具にすることも続けました。

    AI エージェントと、一緒に開発する

    生成 AI を「呼び出す」段階から、AI エージェントと「一緒に働く」段階へ進んだのが今です。Spring AI で YouTube の MCP サーバーを作り、Vertex AI Search と Gemini で RAG を組んだ MCP サーバーを Python と Go と Kotlin で試作しました。AI に道具と知識をどう渡すかを、プロトコルのレベルで確かめています。
